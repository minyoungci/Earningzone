# 데이터와 구현 한계

해석은 입력 데이터가 관측한 범위 안에서만 유효합니다. 플랫폼은 계산값, 수동 가정, 외부 데이터가 더 필요한 개념을 구분합니다. 설명의 기준은 현재 코드이며 개인 자료에 기록된 전망·가격·확률을 현재 종목의 입력값으로 사용하지 않습니다.

## 데이터별 역할

| 데이터 | 현재 사용 | 제한 |
|---|---|---|
| OHLCV | 지표·피벗·리테스트·거래량·갭·백테스트 | 최대 200봉, 제공자별 수정주가·시간대 확인 필요 |
| 현재가·호가 | 평가·모의 체결·호가 불균형 | 시점 차이와 유동성·실체결을 보장하지 않음 |
| USD/KRW | 모의 원장의 원화 환산과 위험 계산 | 과거 환율 경로를 재생하는 성능 검증은 별도 |
| VIX·VVIX·SPX·TLT·UUP·HYG | 시장 레짐 가드 | 여섯 입력의 지연·누락을 구분해야 함 |
| 지연 옵션 스냅샷 | 옵션 거래량·활동성 표시 | 방향성 주문 흐름이나 만기별 실시간 IV가 아님 |
| 뉴스·경제·실적 캘린더 | 참고 맥락 | OHLCV 갭과 이벤트의 인과관계를 자동 인증하지 않음 |
| 직접 입력한 앵커·IV·비용 | 수동 시나리오 | 자동매매 정책에 저장되지 않음 |

TLT 가격 변화는 국채 관련 대리값이며 MOVE 지수 자체를 관측한 것이 아닙니다. 여섯 구성요소로 만든 레짐 점수와 단계도 구현 휴리스틱입니다. 차트 확인 정책은 가드가 켜져 있으면 구성요소 전체가 유효해야 신규 진입을 허용합니다. 기본 정책과 다른 메뉴의 누락 처리까지 동일하다고 가정해서는 안 됩니다.

## 구현된 해석과 추가 입력이 필요한 해석

현재 계산 가능한 것은 확인 피벗의 구조, 고정 ATR 구간, 순서가 있는 리테스트, 두 피벗의 RSI/MACD 다이버전스, RVOL과 가격 방향 거래량 대리값입니다. 이를 일봉 차트 확인 모의 정책의 필터와 목표·손절·수량에 적용합니다.

시장 폭, ADD/TICK/VOLD, 실제 매수·매도 체결 델타, 기관별 수급, 옵션 매수·매도 방향과 포지션 의도, 만기별 IV, 실적 발표 원자료와 기대 대비 서프라이즈는 OHLCV만으로 복원할 수 없습니다. 별도 피드와 검증이 필요하며 현재 정책의 입력으로 구현되었다고 설명하지 않습니다.

## 시간과 관측 범위

완성 봉 판정은 일봉의 UTC 날짜와 분봉의 시간대 정보를 사용합니다. 거래소 휴장일·조기 마감·실시간 완성 플래그를 완전히 처리한 달력 엔진은 아닙니다. 일봉 7일·분봉 15분의 stale 판정도 경과 시간 기준입니다.

최대 200봉은 장기 시장 사이클과 충분한 표본 밖 평가에 부족합니다. EMA200은 정확히 200개의 완성 봉이 있어야 첫 값을 만들 수 있어 당일 봉 제외 후에는 표시되지 않을 수 있습니다. 가격 고저 범위의 내부 명칭이 52주를 가리켜도 실제 관측 기간을 함께 확인해야 합니다.

스크리닝 순위, 캐시된 지표, 현재가와 레짐의 관측 시점은 다를 수 있습니다. 상태·오류·단위·확인 시각을 먼저 확인하고 누락을 0이나 평시 신호로 해석하지 않아야 합니다.

## 공개 배포 문서

배포에 포함하는 문서는 이 디렉터리의 지정된 설명 글 6개입니다. 런타임 문서 API도 이 목록만 읽고, 검색은 공개 글의 본문만 대상으로 합니다. 개인 금융 원문·사본·출처 목록·그림·수집 기록은 앱의 문서·이미지 API나 공개 패키지로 제공하지 않습니다. 개인 자료 폴더는 작성자의 로컬 보관용으로 유지합니다.

ZIP은 선택한 소스·정적 프론트·공개 문서와 파일별 SHA-256 목록을 포함합니다. EXE 빌드도 지정된 공개 글만 포함합니다. 로컬 계좌 상태, 키·토큰, 임시 검사와 이전 배포 보관본은 공개 대상에서 제외합니다. 공개 문서에는 개인 파일 링크, 계정 식별자, 수집 이미지 또는 당시의 개인 거래 사례를 넣지 않습니다.

| 내용 | 기준 코드 |

| 특징·전략·집계·순위 | `features.py`, `strategies/`, `analysis.py`, `quant.py` |

코드 경로는 `tossbot/` 아래입니다. 개발 환경에서는 `python -B -m pytest tests -q -p no:cacheprovider`, `web` 디렉터리의 `npm test`와 `npm run build`로 검사합니다. 데스크톱 `--selftest-report`는 외부 인증 없이 패키지의 내장 서버·프론트·공개 문서를 검사합니다. 이 결과는 실거래 인증 또는 투자 성과 검증과 구분합니다.
